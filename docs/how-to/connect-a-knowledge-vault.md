# Connect a knowledge vault (Obsidian, or any Markdown editor)

Agentheon is plain Markdown with YAML frontmatter — every agent, skill, and team
file is a `.md`. That means a Markdown knowledge base (Obsidian, Logseq, VS Code,
`grep`) can read and cross-link the pantheon directly, no export step. This guide
wires the repo into a vault so you can browse deities, follow handoff edges, and
edit source in your editor of choice.

> Prerequisites: the Agentheon repo cloned locally, and a Markdown editor. Steps
> below use Obsidian as the concrete example; the ideas port to any tool.

## 1. Open the repo as a vault

In Obsidian: **Open folder as vault** → select your `agentheon/` clone. The whole
pantheon appears — `agents/<deity>/README.md` is each agent's source of truth,
`team/` holds the shared context, `docs/` the documentation.

Keep the vault pointed at the **repo**, not a copy. You are editing source that
`hack/gen-*.sh` regenerates from — edits flow into generated `SOUL.md` and
`routing.md` on the next generate run.

## 2. Make handoffs navigable as a graph

Each agent's frontmatter already declares `handoffs:` — the routing edges. To see
them as a clickable graph, add wiki-links in the body of an agent that mirror its
handoffs, e.g. in `agents/zeus/README.md`:

```markdown
Routes to: [[athena]], [[hephaestus]], [[argus]], …
```

Obsidian's graph view then renders the pantheon as the directed routing graph —
the same edges `team/routing.md` encodes as a table, now visual. (`[[athena]]`
resolves to `agents/athena/README.md` if you enable "shortest path" link
resolution.)

## 3. Read the generated map, don't hand-maintain it

`team/routing.md` is generated by `hack/gen-routing.sh` from frontmatter — treat
it as read-only in the vault. When you change an agent's `domain` or `handoffs`,
regenerate rather than editing the table:

```bash
hack/gen-routing.sh          # rewrite team/routing.md
hack/gen-routing.sh --check  # CI-style staleness check
```

## 4. Keep vault clutter out of Git

Obsidian writes a `.obsidian/` workspace folder. Ignore it so it never lands in
the repo:

```bash
echo '.obsidian/' >> .gitignore
```

## 5. Edit source, then regenerate

The loop when working from a vault:

1. Edit an agent's `README.md` frontmatter or body in your editor.
2. `hack/validate-agents.sh` — lint the change.
3. `hack/gen-routing.sh` — refresh the routing matrix.
4. `hack/gen-hermes-profiles.sh` — regenerate each `SOUL.md` (needs the `hermes`
   CLI; it merges into the managed block and preserves your hand-written notes).

Your vault is now a live view of the pantheon: browse it as knowledge, edit it as
source, and let the generators keep the derived files in sync.
